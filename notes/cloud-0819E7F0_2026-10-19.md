# Cloud task 0819E7F0: Hresvelgr burst phases (2026-10-19)

Tags: #matching #hresvelgr

All six functions matched: 0819E7F0 (Hresvelgr_UpdateGroundSlam), 0819E978
(Hresvelgr_UpdateHazardVisit), 0819EC08 / 0819EE68 (recoil burst phases),
0819F0D4 / 0819F2B4 (random burst phases). Names are tentative.

Techniques that decided the last bytes:

* **Separate locals vs one scratch struct.** 0819F0D4 reads its angle table with
  `add rX, sp, #0x10; adds r0, r0, rX` while the id table uses
  `add r0, sp, r0; adds r0, #8`. That is three separate locals
  (`u32 ids[2]; u32 angles[2]; struct ReactionVector pos;`), not the
  scratch struct its 0819ED6C sibling uses. The recoil phases (0819EC08) keep
  the sibling's struct.
* **Helper argument aliasing.** The ROM computed `&pos` once for the polar
  helper and kept a copy for the add; `polar(&pos, a, 256); p = &pos;
  add(p, &actor->position, p);` reproduced the copy and the rematerialised
  `add r1, sp, #0x18`. A script tried all 32 combinations of which argument is
  `p` versus `&pos` (four had the best score).
* **The temporary for the angle** (`u32 a = angles[v]`) fixed register pressure
  but moved `add r4, sp, #0x18` after the load; separate locals then fixed both.
* **`muls` by a constant:** `t * m` with `s32 m = -128;` declared in the block
  keeps `movs; rsbs; muls` (0819F2B4); a literal `-128` becomes shifts.
* **`variant * 64` vs `variant << 6`:** as a helper argument, `* 64` puts the
  shift after the following constant loads (0819EC08); `<< 6` hoists it.
* agbcc pads struct members of struct type to 4 bytes: an `s16 x, y, z` vector
  inside a struct takes 8 bytes.
* `u8 st = 2; p->state = st;` hoists the constant before the address
  (0819E978); `u32 mask = ...;` declared before a pointer local hoists its
  `ldr` likewise (0819E7F0).
