# w3 notes

- sub_080FF7AC: skipped after ~6 attempts. `return (*(u16*)(p+0xC8) & mask) != 0;` compiles
  leaf-style (negs/orrs/lsrs), but the ROM has `push {lr}`, `bne` + `movs r0,#0; b`, `movs r0,#1`,
  `pop {r1}; bx r1`. Variants with if/else, default-initialised ret, and ternary did not reproduce it.
- tooling: a src/fn file whose function signature is not detected by split.py (e.g. a file
  containing literal `\n` text) is silently dropped from the C units, and build.py prints
  `build/boktai3.gba: OK` even though nothing was compiled. Consider failing when a src file has no functions.
- sub_080FE64C: skipped after ~4 attempts. Original computes `p+0xDC` into r2 (`adds r2, r0, #0`) before
  loading the gUnk_02000580 pointer; C codegen reuses r0 for it. Pointer-local and direct-store forms both gave the same object.
- sub_08103A54: skipped. Object matches the original function body (checked with objdump), but the full
  ROM grows by 16 bytes (16777232 vs 16777216) and the first difference is at 0x08001482, the same
  shifted-ROM symptom as the pilot's notes. The function is followed by a `.byte` block (_08103A84) that
  is referenced from data region. Likely a tooling issue with trailing data after a C function.
- sub_081093AC: skipped. Original does not narrow the `u8` value (`adds r1, r0, #0` then `strb r1`); every C form tried
  (u8 / u32 parameter) emits `lsls r0,#24; lsrs r1,r0,#24` first.
- sub_081093C4: skipped. Object body matches, but the original has a label `_081093DC:` right after the literal
  pool (trailing label, referenced by nothing visible), and the ROM differs. Likely the same trailing-data issue as above.
- sub_0810C1E8: skipped after 3 attempts. The original is a leaf (`mov ip, r0`, no push); every C form
  compiles to `push {r4, lr}` with r4 used as a scratch register.
- sub_0810BD8C: skipped after 3 attempts. The loop body (`if (i == 0)` with a do/while over i <= 0) matches the
  shape, but agbcc uses r4 for the `0x98<<1` offset (`movs r4, #0x98`) where the original uses r0.
