# w0 notes

- 08002658: skipped. Target copies the struct pointer into r1 and loads the table base into r2 (`adds r1, r0, #0` / `ldr r2, =0x02000010`), then stores zero via r2. Variants of `gUnk_02000010[p[0x1b]] = 0;` all pick r0 as the pointer register and r1 for the zero, so the store sequence differs. Gave up after about 9 builds.
- 08003460: skipped. Target is `if (p) r = p[0x1C]; else r = 0;` with the ldrb result in r0 and a shared epilogue, but agbcc puts `movs r1,#0` before the cmp (or uses an early return that drops the epilogue). Tried ternary, early return and if/else with result var. Gave up after about 5 builds.
- 0800347C: skipped (tooling). The function itself is a plain `if (gUnk_02000468) gUnk_02000468[0x1A] = v;`, but adding its C unit next to 08003448 changes ROM bytes at 0x08001482, inside AgbMain (`47f2 96f8` becomes `47f2 98f8`), so the whole-ROM build fails at that address. Same symptom the pilot notes describe for trailing data. Not investigated further.
- 08006FAC: skipped (tooling). The C body (list insert into gUnk_02000030 + 0x28) is correct in shape, but adding its unit alone changes ROM bytes at 0x08001482 inside AgbMain (`96f8` becomes `98f8`), so the whole-ROM build fails at that address. Same symptom as 0800347C.
- 08008F64: skipped. Target uses only r0-r3 with `push {lr}`; every variant (reordered loads, temp for p+6, u16 indexing) pulls in r4 for the sum. Gave up after 4 builds.
- 08008A70, 08003734, 08009E3C, 0800CBE0: skipped (tooling). Each C body reads as the asm, but adding any one of them alone changes ROM bytes at 0x08001482 (inside AgbMain), so the whole-ROM build fails there even though the candidate's own bytes were not compared. The same symptom came up for 0800347C and 08006FAC. The trigger is not obvious: the C units are not referenced from that address, and c_labels.ld has `_0800XXXX = sub_0800XXXX__addr + off` entries for internal labels of these functions. Worth a tooling look: the first-difference reporting points at an address that can precede the changed function.
