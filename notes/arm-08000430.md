# sub_08000430: unpinned exact match, and how it works

Tags: #matching #compiler #register-pinning #arm

The ARM sprite/OAM builder at 0x08000430 (src/iwram_code.c, 2,656 bytes) was
exact only with a pinned `register s16 *h asm("r3")` in each emit branch
(PR #845). An outside researcher (GPT-6 Pro, given the package from our round-4
work) found plain C with no `asm` and no named registers. This note records
the mechanism and the lessons that apply elsewhere. Our own dumps from the
instrumented cc1 (`AGBCC_DUMPPRI`, `-da`) agree with each step below.

## What the ROM needed

1. The long-lived cursor address `&gUnk_030042E8` lives in sl and is loaded in
   the loop preheader in a set order (K, E, T, A, F).
2. The tile-space test inside the loop loads the same address again, into r2.
3. The request-count address `&gUnk_03004304` is in r8.

Writing `c = &gUnk_030042E8` gives gcse a plain SYMBOL_REF. PRE then merges
the test's load into it, and the registers and schedule both move.

## The C

```c
/* first branch, before the loop */
cursorLastByte = (u8 *)&gUnk_030042E8 + sizeof(gUnk_030042E8) - 1;  /* &g + 1 */
cursorBase = (s16 *)(cursorLastByte - (sizeof(gUnk_030042E8) - 1)); /* back to &g */
for (...) { cursor = cursorBase; ... }
/* second branch */
cursorEnd = (u8 *)&gUnk_030042E8 + sizeof(gUnk_030042E8);           /* &g + 2 */
cursorBaseZ = (s16 *)(cursorEnd - sizeof(gUnk_030042E8));
for (...) { cursor = cursorBaseZ; ... }
```

Byte pointers keep both displaced addresses inside the object (or one past
it), so this is defined C. Neither displaced pointer is dereferenced. The unit
also turns the old IW_QUEUE_TILES macro into a `static inline IwAllocTiles()`.
That helper keeps the dead initializer `u8 *b = 0`, because removing it changes
the output.

## Why it works, one pass at a time

| Pass | What happens |
|---|---|
| cse1 | `base = off - 1` stays as arithmetic (cost 2, against 12 for a symbol load) and gets `REG_EQUAL &g`. The loop copy `c = base` gets no note, because cse1's knowledge stops at the loop label. |
| gcse | `hash_scan_set` hashes `SET_SRC` and ignores REG_EQUAL notes, so it sees `(const (plus g 1))` and `off - 1`, not `g`. The test keeps its own `ldr =g`. |
| loop | `c = base` is invariant and is hoisted into the preheader, still as a plain register copy. |
| cse2 | The hoisted copy now follows `base`'s definition on an extended path, so it gets `REG_EQUAL &g`, in both branches. |
| combine | Inside the pre-guard block, `off = g+1; base = off-1` folds to `base = g`. The copy is across the guard, so the fold doesn't reach it. |
| sched1 | It schedules E as a copy, which gives the ROM order. A symbol load at this point gives the wrong order (the sim3 result). |
| lreg | `update_equiv_regs`: `base` has exactly 2 refs (one def, one use) across blocks, so it is deleted and the copy becomes `c = g` with REG_EQUIV. |
| global | Two REG_EQUIV defs double c's live length twice (142 → 568), so its priority is 3·14·10000/568 = 739. It ranks below the r8 request count (757) and gets sl. |

## Controls (each changes one property; all fail)

| Change | Size | Differing words |
|---|---:|---:|
| The same offset (+1) in both branches | 2672 | 214 |
| One expression, `(s16 *)((u8 *)&g + 1 - 1)` | 2656 | 24 |
| Recover `base` inside the loop instead of before it | 2672 | 185 |
| One shared `base` for both branches | 2664 | 189 |

* With the same offset, gcse shares the displaced symbol above the branch.
* One expression folds before gcse, so the merge comes back.
* Recovering inside the loop puts the producer and the subtraction on opposite
  sides of the guard, so combine can't cancel them.
* A shared base has 4 refs and fails the `REG_N_REFS == 2` check.

The 24-word control shows the same lesson as the PDF: never rank drafts by
diff count. It has the right size and a small diff, but it is structurally
wrong.

## Lessons that apply elsewhere

* **Hiding a symbol from gcse without asm.** Derive the address as
  `(u8 *)&sym + k`, then subtract `k` in a separate statement. gcse hashes the
  executable source, not the note, so the merge never happens. combine and
  local-alloc then fold the round trip away, and no extra instructions are
  left. Use a different `k` per branch if both branches need it, so the
  displaced constant can't be shared either. Wider carriers (an s64, a union)
  survive gcse, but they don't fold away later.
* **Separate statements are separate RTL.** `a = x + 1; b = a - 1;` and
  `b = x + 1 - 1;` are equal in C but not in the compiler. The first keeps the
  arithmetic until combine; the second folds at expand or cse1.
* **Basic blocks decide what combine can fold.** combine links only within a
  block. Put a producer and its consumer before a guard to let them fold, or
  on opposite sides to keep them apart.
* **The `REG_N_REFS == 2` substitution.** A pseudo with one def and one use,
  whose source matches its REG_EQUIV, is deleted in local-alloc and its value
  is put into the use. Earlier passes saw a register copy at that point. Two
  variables, one per branch, keep this; one shared variable loses it.
* **REG_EQUIV lowers priority.** Each constant-equivalent def doubles live
  length in update_equiv_regs. A pointer to a constant address that gets a
  register "too good" may need a REG_EQUIV def on every path.
* **Temporary RTL feeds heuristics.** An instruction that disappears later
  still counts in earlier decisions. In the height-table draft, naming a
  width-table pointer outside the loop took one insn off the loop count
  (77 → 76). That passed loop.c's test `threshold × savings × lifetime ≥
  insn_count` (19·2·2 = 76), hoisted the 1023 constant into r8, and caused
  spills.
* **Method.** Before writing C, state the required compiler state for each
  pass (requirements 1-3 above). Find the first pass whose dump disagrees,
  write a hypothesis you can check against that dump, and then change one
  property at a time. A wrong register at greg usually started at gcse or
  earlier.

## Status of the source

This is a matching reconstruction, and the researcher says so: the byte
offsets are not likely the original authors' text. It meets the project
rules, though: plain C, with no `asm()`, no named registers and no
instruction bodies. A more natural spelling that gives the same pass states
(for example, a macro or inline helper that takes the address as a byte
pointer) would be welcome.
