# s1 notes

## Tricks
- `if (a || b) r = 0; else r = 1; return r;` reproduces "bne ret0; call; beq ret1; ret0: movs 0; b end" layouts (0804EB38); plain `&&`/early returns do not.
- Declare the constant local first (`u32 m = 1;`) before pointer init to get `movs r3,#1` before the pointer setup in a loop (0804D874).
- Nested `if (a) { if (b) return 1; } return 0;` matched where `&&` into a result var did not (0804EA38).
- Switch with cases 2 and 3 sharing a body but compiled as separate `cmp #2; beq; cmp #3; beq`: write two separate `case 2:` / `case 3:` blocks with identical bodies (cross-jump merges them); `case 2: case 3:` gives a `bgt` range test instead (08064918, 08064954).
- Wrapper ending `pop {r1}; bx r1` that just forwards args: make caller and callee `s32` and `return callee(...)`; extra stack args are just more params (08066A88, 08066AB4, 080684D0).
- Function that stores `r = callee(); *(u16*)... = r;` and has epilogue `pop {r1}` with `adds r2,r0,#0` copy: declare `u32 r = 0;` return type u32, fall off the end (08061CA8).
- Big-offset object accessors match with plain `u8 *p` + `*(T *)(p + off)` casts when no arrays are indexed; most were first-try.
- Local copy of a ROM table: `struct T { u32 a,b,c; }; extern const struct T gUnk_...; struct T t = gUnk_...;` gives ldm/stm (080638BC).
- Table-search loops: `s32 i = 0;` at decl (movs before the ldr), and `p++, i++` order controls adds order (08060528).

- (R3) Non-void leaf that falls off the end (`u32 f(void){ g = 0; }`) puts the zero in r1 and address in r2 (matches `ldr r2; movs r1,#0; str`); with `void` zero lands in r0 (08073B78).
- (R3) `ldr r2,[r0]; cmp r2,#0; ... bl callee` where the loaded value stays in r2: the callee takes it as a hidden 3rd arg (0806FC24, 0806FC64, 0806FD08).
- (R3) Mask-before-load for `*q &= m`: `u16 *q = ...; u32 m = ~8; *q = m & *q;` (declare m AFTER q) matched 080B12AC; `-3` not `~3` for movs/rsbs form (080C515C).
- (R3) 'create singleton' wrappers (alloc, register 2 callbacks, init <0 -> free,return 0) copy the sub_08100068 shape exactly (0806BA00, 0806CEC0, 0806E250, 0806F954).
- (R3) Callee u16 param + caller u32 param: caller truncation appears at the call site only if the callee prototype says u16 (0806B5B0).
- (R3) Scanning loop returning a ptr: `r = q; goto end;` + `r = 0; end: return r;` form matched where early `return q` did not (0806F9AC).
- (R3) Tooling: callback 0x0806F54C (and 08070444, 08070E44) still not discovered as functions in gen/ (stay raw .incbin/.byte).

## Skips
- 0804EBD8: Div(v*x,0x8c) with v ternary from ptr; target copies v to r2 (`adds r2,r0; muls r2,r1,r2; adds r0,r2`), all variants (u32/s32/u16, v*=x, x*=v) give `muls r0,r1,r0`.
- 0804E730: `if (f&0x20) r=2; else r=(f&0x10)!=0;` target uses `rsbs r0,r1; lsrs r1,r0,#31` in else branch and branches before loading 2; mine speculates `movs r1,#2` before cmp. 3 variants.
- 0804EAFC: loop over i<p->n with q=p+i*0xa8 (flag at +0xc9, call with +0x34). Target keeps p in r4/i in r5 and mul via `adds r1,r5,#0; muls r1,r0,r1`; mine swaps r4/r5 and muls into r0. ~8 variants incl. struct-less casts.
- 0804EED0 (twin of 0804EAFC): real struct (u8 n at 0x26, struct E e[] at 0x34 size 0xa8 w/ flag at +0x95) fixes the r4/r5 and mul registers, only remaining diff is call arg: target 'adds r0,r1,r4; adds r0,#0x34' vs mine 'adds r0,r1,#0; adds r0,r4,r0; ...' (extra mov). ~6 variants.
- Operand order of an indexed load (adds r0,r0,r1 vs adds r1,r1,r0): write `*(s32 *)((u8 *)tbl + (i << 2))` instead of tbl[i] (08056F20).
- If the target keeps an unexplained copy of a pointer in r1 (`adds r1,r0,#0`) across a call, the callee takes extra (leftover) args: declare it with them and pass p, p->a (08055BA8).
- 08055DA0: loop matches, but epilogue `movs r1,#0; ldr r0,=gUnk; str r1,[r0]; movs r0,#0` (store 0 and return 0 NOT merged) vs agbcc merging into one zero. tried u32/void*/volatile. same shape as the 'return *p = 0' tip but without merging.
- 08059264, 080592AC: timer++ then `if (t >= p->max) {call(p->h); p->x=0; p->t=0}` with zero in r6 (callee-saved) set between the add and the strh; agbcc orders movs r6 before the ldrh or inserts the u16 truncation (lsls/lsrs) before the strh. 5 variants (z decl position, u16 n temp).

- 08065BEC: alloc-slot loop (mask u32 at +0xA1C, 8 elems stride 0x138 at +0x5c, idx byte at +0x99; returns elem or 0). Target keeps const 1 in r7, &mask in r3, two pointers r4/r5 stepped by r6=0x138, bit test as unoptimized bool (`beq; movs 1; b; movs 0; cmp; bne`) with `1<<i` recomputed. 5 variants (struct array, u8* ptrs, inline tst helper, ternary, `one` local): mine always puts the stride in ip/r7 and loop var in r5.
- 08065C40: 'bl f; cmp r0,#0; bne; movs r0,#0' (return f(); but with explicit zero on null) is folded away by agbcc in all forms tried (if r==0 r=0; ternary).

## Overnight tricks (round 2)
- Stack-struct init pattern (`ldr r0,[sp,#0xc]; ands 0xFFFF0000; orrs lo; ands 0xFFFF; orrs hi<<16`): use `struct H { u32 lo:16; u32 hi:16; }; struct Z { struct H a, b; };` with `s1.a.lo=..; s1.a.hi=..; s1.b.lo=..;` for the first, and `*(u32 *)&s2.a = V; *(u32 *)&s2.b &= 0xFFFF0000;` for the second (whole-word store + mask). A mask loaded BEFORE a `movs 0`/store needs `{ u32 m = 0xFFFF0000; z.x = 0; z.y &= m; }` in an inner block (0804F4AC, 080561E8). 15+ functions in this family (callee 0821FEB4/08074BF4/08074D34).
- Switch on d with `cmp 1;beq;cmp 1;bgt;cmp 0;beq` = nested `switch(d)` with cases listed 0,1,2,3 and shared `st:` labels via goto into other case (08064B70).
- Shared tail returns: `if (x) { ...; no: r = 0; goto done; } else { if (y) goto no; } yes: r = 1; done: return r;` to force block order (08049818, 08050310 uses `goto yes/no` with trailing `yes: return 1; no: return 0;`).
- `*(u16*)(p+off) = bigconst` gives `adds r0,r2,#0` copy; storing through a struct member (`((struct Q *)g)->v = 0x5dc;`) removes it (0804FE20, 08049EBC).
- To force `movs const` AFTER an address calc: compute pointer into a local first (`q = &p->f; z = 0; *q = v;`) (0804F5F4, 080582B8, 080586C0, 0804D954).
- To stop agbcc folding `ptr+0x124` then `[1]` into one literal, assign the pointer var after an earlier store (080638F8).
- `(u16)v` truncation shows only if v is `u32` and cast is explicit; `s32 t = *(u16*)..; t >> 4` gives `asrs` on an ldrh (0807E6FC content).
- Bool-return that ends with `pop {r1}` and loads r0 then falls through: declare `s32 r = global; if (r==0) { r = f(); } return r;` (0804EF78).
- 080C47B8: three (u16&0xFFFFFF00)+0x80: target ldrh before ldr mask const, mask copied 'adds r1,r2,#0'; mine ldr first / mask folded to 0xff00. 6 variants. 08051A3C: t=p->t+1 kept in r2 unextended with ext copy in r0 (u32 vs u16 both off). 080497F0: -1 stored via movs/rsbs/adds r1,r2,#0 (see 080B0C80). 080492F0: 0x3e4 offset const derived (subs r3,#0x28) vs target movs/lsls.
- 08074600 (if b==0 {r=f1(a); if r==-1 b=0,goto call} else call f2(a,b)): structure matches with goto, but b copied to r5 (range-based alloc). 0809CC8C: s32 i=(u16)>>7 target keeps 'lsrs r0; adds r1,r0,#0' copy, mine direct. 080F3B30: 'movs r0,#1' before 'adds r2,#0x8d' of byte-or (3 variants).
- 080DE550 (p->a=f(id); p->b=g(id)): target copies result 'adds r1,r0,#0' then stores r1 via computed addr r0; mine stores r0 directly (6 variants). 0810BD8C: single-iteration loop (i==0 test), const 0x98<<1 reloaded inside loop in target; mine hoists to r4.
- 08072C80: list search with g==0 test: target layout 'bne L; b ret0; pool; L: found-block...' (return-n block placed before loop); 3 variants no luck.
