# s0 notes

## Tricks
- 08001EB4: skipped. Loop over p->e[] (stride 0xc) matching id; everything right except e/i swapped (orig e=r2,i=r3; mine e=r3,i=r2) across 5 declaration-order variants.
- Loop `for (i=0;i<n;i++,e++)` vs `e++,i++`: the order of the increments in the for-expression sets the order of the adds. Early `return` inside the loop (instead of break) can change hoisting of constants (08003B84).
- Develop in untracked wip/NAME.c (check.py accepts a path), copy to src/fn only on match: build.py compiles everything in src/fn so one failing file breaks the OK check.
- 08003BB8: skipped. Push (u16 a, u16 b as raw u32 params) into s->arr at 0x2c stride 4 indexed by s->n (0x28); orig computes (s+0x2c)+n*4 unfolded, twice, re-reading n; mine always folds #0x2c into strh offset.
- `if (cond) {...; return 0;} return -1;` may lay out differently from `if (cond) {...; r = 0;} else r = -1; return r;` -- use the latter when the original has the failure block last (09524).
- To get `movs rN,#imm` before the memory load in `x->fl & 4`, declare `u32 m = 4;` before the `if` (08008ABC).

- 080096A0: skipped. flags test (o=t->o; fl&0x186C; fl&0x100000; t->sg<0). Logic right; orig loads o, then the 0x186C literal, THEN o->fl; mine loads o->fl before the literal. Also note: (fl&A)==0 && (fl&B)==0 gets merged into one test by agbcc, so use separate early-returns.
- Tail `movs r1,#0; ldr r0,=G; str r1,[r0]; movs r0,#0` (store 0 to global, then return 0): write `{ u32 z = 0; G = z; } return 0;` (0800A500, 0800AB18).
- BIG: non-void function that falls off the end without `return` (e.g. `u32 f(..){ ...; s->v = 0; }`) gives the `pop {r1}; bx r1` epilogue with r0 left as garbage (0800A80C). Use when asm returns value but r0 is stale.
- 08002A04: skipped. Push into struct stack: (idx,id,cnt,src); s=gUnk_02000010[idx] (n at 0x64, ids u16[8] at 0x68, data u16 at 0x78+n*16+i*2). Orig copies all three args to r4/r5/r6 and keeps s in r2; mine keeps cnt in r2, s in r3 (3 callee regs vs 4).
- Real struct with array member (b->t[a->i]) gives base+idx operand order that pointer-cast code does not (0800E0CC). Guard `if (G != 0) return G;` makes the early exit return the loaded value in r0 (0800D828).
- 0800EA94 / 0800EBB0: skipped. State tick (sub_0800E7D8()==0; cnt u16 at 0x2d8++; if cnt>=lim(0x2ba) set fn ptrs at 0x2cc/0x2d4 (sub_0800E974, sub_0800F0F0), cnt=0; fl |= 0xf). Orig derives 0x2cc/0x2d4 from the 0x2ba reg via adds r2,#0x12/#8 (scratch r2); mine keeps the constant in callee-saved r5 and pushes it.
- A loop step held in a register (`movs r7,#2 ... adds r4,r4,r7`): declare `s32 k = 2;` and do `p += k` (080115A4). Loading args into locals first (`u32 a = in[0]; u32 b = in[1]; f(s->p, a, b)`) controls load order before the call.
- Loop `for (i=7;i>=0;i--, e++)` vs `e++` in body: `subs` before `adds` needs the for-increment form; the reverse needs e++ at body end (08012630 vs 0800A830).
- Constructor boilerplate (alloc 08219FBC, init 0821A04C(p, fnA, fnB), setup, if <0 free 0821A0C0 return 0) compiles from a plain C template; see 08006144.
- Tooling: worklist flags 080039F0 as JUMPTABLE but it has none (trailing code bytes labelled as data). 08003860 (real switch table) matched first try with a plain C switch.
