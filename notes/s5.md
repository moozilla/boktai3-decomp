## Tricks
- `(u32)-(x & 0x80) >> 31` gives rsbs/lsrs #31 sequence (sub_082144A4); store args to temp before the zeroing stores.

- sub_08215AC4: sibling of matched sub_08215A74 (BGxCNT priority set, `(*r & 0xFFF3) | (v<<2)`); orig loads ldrh into r1 and mask into r0 (`ands r0,r1`; `lsls r1,r3,#2`; `orrs r0,r1`), mine swaps r0/r1. Tried 4 expression orders.
- sub_08215490: zero u16[4] at 03004790 via descending do-while with signed compare (`adds r0,r1,#6 ... bge`) + 0x7f-iteration loop writing 0x200 to 8-byte entries at 03004390. Got everything but literal-load order (orig loads r4=0300479C,r5=03004BA0 before r1=03004790) and `movs r0,#0x7f` placement.
- sub_08216520: two `t<0 ? -(-t>>3) : t>>3` (blt first, asrs; b; rsbs...) then BgGfx_LoadTilemap(a,px,py&~1,x,c,0) with 6th stack arg; semantic OK but orig keeps c in r3 (copy) and does `adds r2,#0x50` in place, px in r1/py in r2; mine uses r6 push and different reg assignment (5 attempts).
- MMIO mirror stores (`gShadow = v; REG = v`): write `gShadow = expr; *(vu16*)REG = gShadow;` (non-volatile global reread is CSE'd) - sub_08216F78. Chained assignment `REG = gShadow = expr` gives worse regalloc.
- OR-chains: operand order matters for dest reg; `b | (c<<8) | (a<<6)` vs `(a<<6)|...` - try all permutations (sub_08217060).
- `switch (s32 n)` for case 0..3 gives cmp#1/beq/cmp#1/bgt layout; unsigned n gives blo layout (sub_08215A74).
- Descending signed-compare loops need a do-while.
- sub_08217298: loop of 2 `*p |= 0xFFFF` (ldrh/orrs/strh) with mask pre-loaded into r3 (`ldr r0,=0xFFFF; adds r3,r0,#0`), push{lr} only; agbcc folds |0xFFFF into plain store or uses r4. Tried vu16, u16/u32/s32 mask var.
- sub_08217E40: same as 082144A4-style tail (c&0x80 flag then call sub_082143CC) but orig has o in r3, c in r2 (mine swaps them).
- sub_08217D50: nested copy loop (palette entries: for i<gUnk_030051CC { src=gUnk_030042E4+(gUnk_030051F0[i]<<5); dst=gUnk_03004DC0+i*32; 16x u16 copy }) - orig has i in r3, computes i+1 into r4 before inner loop and moves back after (inner j reuses r3). Mine keeps i in r4 / j in r3. Moving i++ before inner loop made it worse (strength reduced).
- sub_08218ED8: fill rect of Video_GetBackgroundMap(0) (32-wide u16 map) with 0xF001, args x,y,w,h. Orig: x copied to ip, inner col var r6=ip each row, r5=x<<1 hoisted, r1=y+1 hoisted before inner loop, r8=map; Tried u16* / u8* variants, never got the hoisting.
- ARM trampolines (sub_08219624/0821962C/082196A4 etc: thumb `push{lr}; add r1,pc; bx r1` + arm_func bodies) skipped: not C.
- Operand order for `base + idx*4`: write `(u32 *)((idx << 2) + (u32)tbl)` to get `adds r3, r0(idx<<2), r1(tbl)` (sub_08218E0C).
- sub_08219F04 (BgGfx_LoadTiles(src,dst,n): DMA3 in 0x200-byte chunks while n>0x200, then remainder n>>2|0x84000000): orig copies params into r4/r5/r3 (`adds r4,r0; adds r5,r1; adds r3,r2`) and uses r1 as DMA base, r2 as 0x200 copy; mine uses params in place. Tried local copies, while vs if+do-while.
- Trick: to force evaluation order of two sub-expressions (e.g. rotate `(h<<5)|(h>>11)` emitting lsls before lsrs) assign each to its own u32 temp then OR them (sub_08219BD8).
- Trick: `x = gArr + (o->f << 5)` where orig does `ldrh; ldr =addr; lsls` : load the field into an s32 temp first (sub_08219A80).
- Descending pointer loop idiom (`r0=base+6; strh; r0-=2; cmp r0,base; bge`, no counter; seen in sub_08215490 and sub_08219AAC tail `for(i=3;i>=0;i--) gUnk_03005274[i]=0x3FF`): agbcc keeps a counter for the plain index loop, and for an `(s32)p >= (s32)base` do-while it derives base = p-6 (CSE). Not reproduced; sub_08219AAC otherwise matches except this tail + pool order.
- sub_0821A184: find-free-slot loop over 8-byte slots at 0203B000 (count gUnk_030052F0, flags&0x80 = used; after loop count++ and return slot or 0 if count>0x1f). Same as matched sub_0821A1C8 shape but orig puts slot ptr in r2/index in r3; mine swaps (tried decl order, ++ order).
