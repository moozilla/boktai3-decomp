artificial by that fact alone. Conversely, allocation-only C remains source debt
even when the linter misses it.

## Source changes worth reviewing

### Volatile views and real layouts

The two volatile audits change **33 units, 83 functions and 32,284 reviewed
bytes**, removing 44 reported warning lines. Another local view disappears in
the address-expression work, making **45 fewer volatile-view reports** overall.

The first audit removes ordinary-object qualifiers, simplifies two wireless
pollers through their existing shared IRQ-volatile declaration, and recovers
three RFU assignments through the actual volatile byte fields. In those RFU
cases, agbcc itself emits the observed read before the volatile struct-member
store; the old source's explicit discarded reads duplicated it. The dummy-read
statements are deleted while the real IRQ volatility remains.

The follow-on replaces eleven copied animation layouts with
`DisplaySequenceState`, deletes four entirely unused sequence definitions, and
recovers two live operations. `Background_QueueCommand` copies arguments through
the actual indexed command array, removing the volatile count, raw offset
arithmetic and six aliases. `EffectPool_UpdateEntry` uses the existing playback
API, also eliminating two unreported volatile flag casts.

The status-indicator change removes a local volatile pointer through typed
indexed allocation. Its pre-existing shared predicate still accepts a volatile
pointer; the report does not claim all volatility in that path is gone.

### Shared operations and ordinary control flow

**27 once-loop reports disappear through source changes.** Seventeen come from
particle sampling, existing control-packet setters, typed vector assignment,
flag updates and ordinary state/item-use statements. Two more recover the
complete random-table draw shared by contact bursts and presentation shake.
The remaining eight come from direct interaction-marker predicates, actual flash
frame branches and indexed 16-color palette banks.

The new `PARTICLE_RANDOM_DRAW` operation performs only the cursor advance and
selected-halfword read. Both operations already repeat at both caller sites and
in the existing sampler API. It adds no temporary, dummy use or allocation
parameter. Plain blocks and existing inline samplers were tried first. The
header addition and paired mechanical adoption are separate commits; the two
callers were adopted together to avoid an intermediate single-use macro error.
All **84 of 84 header dependents** match independently in the integrated tree.
See [the full operation evidence](round14-random-draw-operation.md).

**18 statement-expression reports disappear** through ordinary conditions,
blocks and real fields in twelve units. The six unresolved terrain/monster sites
remain visible. Exact candidates that merely lifted a wrapper while preserving
alias-only steering were withheld.

### Constants, addresses and placeholders

**57 constant-local reports disappear:** 34 independent lexical-scope locals,
18 in the address/field recovery, four in the shared control-packet changes, and
one in Octopus's restart transition. The scoped pass tests 103 fixed proposals
and accepts 34 in 18 units; all 12,108 bytes match independently. It excludes
address-taken fill values, unknown shadowing and unsafe mixed assignments.

The address follow-up removes **eight address-expression reports**, using actual
typed fields, indexed storage and complete flag operations. The placeholder
follow-up removes **twelve reports** through actual temporary/alias deletion,
shared navigation operations and real field types. A simple rename that would
only evade the detector is not counted as a fix.

`src/menus/hud/hud.c` also loses 928 duplicate `sun_clock.h` includes, leaving the original
first include. All 32 functions and 5,840 bytes match. This corrects an existing
source-corruption artifact and contributes no warning-count credit.

## Exactly one new annotation

File: `src/lib/libgcc/sub_0824AC74.c`, `Libgcc_MultiplyInt64` (`0824AC74`).

`concession-ok(once-loop): GCC libgcc/longlong.h umul_ppmm expansion, called by libgcc2.c __muldi3`

The source is independently verified against the pinned original agbcc/libgcc
commit `da598c1d918402c42c0c0d7128ba14567f3175e9`. Preprocessing the original
`__muldi3` produces the same **447-token body** as the pre-change decompilation.
Its `umul_ppmm` expansion contains the retained loop. The outer statement
expression becomes an ordinary product-assignment block; all 112 bytes remain
exact. Removing the inner loop changes 12 bytes, and a direct-product variant
changes 31. Those failures are recorded; the original source identity is what
justifies the annotation.

This is the only added `concession-ok` in the cumulative series. It is counted
separately from the 27 removed/recovered once-loop sites. Full evidence:
[libgcc multiply source](round14-libgcc-multiply-source.md).
